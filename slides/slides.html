Resilience Testing: Definition & Strategic Value

Resilience Testing is the systematic verification of a system's ability to maintain service continuity and recover gracefully from infrastructure or application failures.

Key Strategic Objectives

  • Risk Mitigation: Proactively identify architectural vulnerabilities before they impact production stability.
  • Measurable Assurance: Utilize Resilience Scores to provide objective data on system hardening and reliability trends.
  • Operational Readiness: Validate automated recovery mechanisms and incident response protocols under controlled conditions.
Faults Controlled injection of specific failure modes (e.g., Pod Delete, CPU Exhaustion, Network Latency).
Actions The orchestration logic governing experiment execution, timing, and sequence of events.
Probes Automated health checks (HTTP, Prometheus, K8s) that validate steady-state compliance during failure.

Demo Scenario & Prerequisites

Prerequisites

  • 1. Kubernetes Cluster: Accessible cluster (Minikube, EKS, AKS, or GKE).
  • 2. Harness Delegate: Standard image (≥ 24.09.83900) installed in the cluster — powers DDCR; no separate chaos agent.
  • 3. Kubernetes Connector: Connector that reaches the target cluster via the Delegate.
  • 4. Resilience Testing Infrastructure: Create under Resilience Testing → Project Settings → Resilience Testing Infrastructures → Kubernetes (Harness Infrastructure).

Demo Experiment: Validating Self-Healing

  • Sample Application: A lightweight nginx deployment with 3 replicas (provided in k8s/ directory).
  • Primary Target: resilience-demo deployment (Namespace: chaos-demo).
  • Failure Mode (Fault): Kubernetes Pod Delete — Simulating unplanned instance termination.
  • Validation (Probe): HTTP Get Probe — Monitoring the service endpoint to ensure zero-downtime availability.
  • Success Criteria: 100% Resilience Score, confirming successful pod rescheduling without service degradation.
